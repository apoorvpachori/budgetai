# Project documentation

- Keep documentation aligned with the implementation. Mark decisions as planned, implemented, or unresolved so agents do not mistake proposals for working features.
- Put user problems, scope, flows, and acceptance criteria in `prd.md`; put durable system boundaries and technical decisions in `architecture.md`; keep the root README focused on product orientation, status, setup, and links.
- Update deployment and API guidance when corresponding behavior changes.
- Never include real statement files, transaction histories, credentials, or other personal financial data in examples.
